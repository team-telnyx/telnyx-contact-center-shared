Secrets stores sensitive values used by integrations without exposing them in ordinary configuration screens. Open **Admin → Configuration**, then select **Secrets** in the rail.

The table shows **Name**, **Description**, **Expires**, **Status**, and edit/delete actions. **Refresh** reloads the list and **New Secret** opens the creation sheet.

## Create a secret

| Field | Required | Description |
| --- | --- | --- |
| **Name** | Yes | Stable unique reference such as `API_KEY_OPENAI`. Choose carefully; it cannot be changed later. |
| **Description** | No | Purpose, owner, or rotation notes. Never place the secret value here. |
| **Value** | Yes on creation | Sensitive value encrypted before storage. |
| **Expires At** | No | Optional date/time used to indicate expiry status. Leave empty for no expiry. |

## Edit or rotate a secret

The current value is never returned to the browser. When editing, leave **Value** empty to preserve the encrypted value or enter a replacement to rotate it. You may change the description and expiry, but not the name.

## Use a secret

Web Page URLs can insert a reference such as `{{secret_name}}`. MCP Servers and supported TTS integrations select a secret by name. Resolution happens server-side; avoid copying raw credentials into URLs, descriptions, logs, or screenshots.

## Delete a secret

Deletion is permanent and may immediately break every configuration that references its name. Search dependent Web Pages, MCP Servers, and integration settings first. Prefer rotation when a credential changes but the reference name should remain stable.
