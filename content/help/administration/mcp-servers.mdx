MCP Servers connects Contact Center to external tools exposed through the Model Context Protocol. Open it from **Admin → Configuration → MCP Servers** or from the **AI Assistants** rail. The `rail=ai` URL keeps the AI rail visible; the default URL uses the Configuration rail.

Each server card shows its configuration and allowed tools. Expand the card to inspect tool names; select a tool to view its description, required input properties, input/output schemas, schema hash, discovery time, and raw metadata.

## Add or edit a server

| Field | Required | Description |
| --- | --- | --- |
| **Name** | Yes | Recognizable connection name. |
| **Type** | Yes | SSE or HTTP transport. |
| **URL** | Yes | Remote MCP endpoint. Use HTTPS for external servers. |
| **Authentication Type** | No | None, Bearer token, OAuth Authorization Code with PKCE, OAuth Client Credentials, API-key header, or Custom header. |
| **Secret** | Depends on auth | Selects a local encrypted secret; raw credentials are not entered into the server record. |
| **Header Name / Scheme / Resource URL** | Depends on auth | Header or OAuth metadata required by the selected method. |
| **Custom Headers** | No | Static header name/value pairs sent on every request, in addition to the selected authentication. Credentials must use the local-secret option. |
| **Allowed Tools** | No | Explicit allowlist of discovered tools available to consumers. |

## Connect and authenticate

Select **Connect** after entering name, type, and URL. This detects authentication requirements and attempts tool discovery. For Authorization Code OAuth, connect first, review the detected resource, then select **Authenticate**. After the callback, review tools and save the final configuration.

OAuth client credentials may be stored as JSON containing `client_id` and `client_secret`, or in the supported `client_id:client_secret` format. For non-Telnyx OAuth resources, provide the resource URL when required.

### External OAuth providers

By default, OAuth Client Credentials requests a token from the Telnyx token endpoint. To use a different provider, add its details to the same secret:

```json
{
  "client_id": "...",
  "client_secret": "...",
  "token_url": "https://login.microsoftonline.com/<tenant-id>/oauth2/v2.0/token",
  "scope": "<application-id>/.default"
}
```

Optional keys: `audience`, `resource`, and `auth_style`. Client authentication defaults to `client_secret_post` for external providers and HTTP Basic for the Telnyx token endpoint; set `auth_style` to `basic` or `post` to override. The `resource` parameter is only sent when set explicitly, because Microsoft Entra ID v2 rejects it.

Tokens are cached per endpoint, scope, and resource, and refreshed automatically before expiry.

### Gateways that require a second credential

Some vendors put their MCP server behind an API gateway that requires a static key alongside the OAuth bearer token. Configure the OAuth grant as the authentication type and add the gateway key under **Custom Headers**, for example `Ocp-Apim-Subscription-Key`. Custom headers are merged with the generated `Authorization` header on every request, including tool discovery.

Tick **Value is a local secret** on any header that carries a credential and select the local secret holding it. The server record then stores only a reference (`{{secret:<name>}}`); the credential itself stays in the encrypted secret store and is resolved server-side at request time, so it is never written to the server record or returned to the browser. Leave the box unticked only for non-sensitive values such as a tenant identifier.

Header names are case-insensitive, and the authentication setting above generates its own `Authorization` header. A custom row named `Authorization` (in any casing) is replaced by the generated one, and the editor warns when you add it.

## Tool discovery and allowlisting

Select **Load Tools** or **Refresh Tools**, review descriptions and JSON schemas, then select only the tools the application should be allowed to call. **Select All** is convenient but broadens integration capability; apply least privilege.

Discovery proves that metadata can be read with the current connection. It does not guarantee every tool invocation will succeed with every argument or downstream permission.

## Delete and troubleshoot

Deleting a server removes its local connection and allowed-tool configuration. Check assistants and workflows for dependencies first. Connection errors commonly indicate an incorrect URL/transport, missing or expired secret, OAuth session problem, invalid client, or insufficient remote scope.
