| Symptom | Checks |
| --- | --- |
| Phone does not open | Use the header phone control; reload only if the UI provider no longer responds. |
| WebRTC URI unavailable | Ask an administrator to verify the profile `telephony_user_name`. |
| Call button disabled | Select a destination and confirm the WebRTC client/profile is ready. |
| No microphone audio | Check site permission, OS input permission, mute state, selected device, and whether another app has exclusive access. |
| No remote audio | Check browser autoplay/output policy, selected speaker, OS mixer, headset connection, and browser output-routing support. |
| No inbound offer | For agents, verify status, queue activation, skills, queue eligibility, browser endpoint, and that the call has not already timed out/re-enqueued. |
| Region selector disabled | Finish the active call; region changes are intentionally blocked during a call. |
| Transfer/consult fails | Verify the call is connected, target is valid, interaction/call-control metadata exists, and target infrastructure is reachable. |
| UI remains on an ended call | Wait for lifecycle events, compare Agent Desktop/server state, then refresh. Do not initiate another operation from a stale call. |

When reporting a fault, include timestamp/timezone, user, interaction ID, direction, selected devices, displayed call state, target type, and exact notification text. Do not include credentials or unnecessary customer data.

## Connection quality

Choose **Statistics** in Calls on to open **Connection quality** during a browser call. It shows estimated MOS, jitter, round-trip time, interval packet loss and incoming/outgoing bitrate, with recent charts. These describe the browser's media leg. Calls handled on iPhone must be measured on iPhone.

Unavailable counters display a dash, not perfect quality. A paused or ended call may have no fresh samples. MOS is an estimate, not a listening test. Metrics remain in browser memory; the panel does not record call audio. Compare problems with headset changes, Wi-Fi/network conditions and the actual selected call device.

## Device selection and handoff

If no call arrives, check **Calls on**, device reachability, agent status and queue activation. Notifications only is different from a ready voice connection. For iOS push standby, confirm the app remains signed in and registered and that its notification/VoIP setup is valid.

If another device owns the interaction, its controls and wrap-up remain authoritative. Use Take over here or the move dialog for a supported move. A pending or uncertain handoff requires reconciliation; do not disconnect the original call or create repeated replacement calls. See [handoff recovery](/help/webrtc-phone/devices#cancel-or-recover).
